# Free hosting feasibility

**Scope update:** this initial cloud comparison assumed a 24/7 worker. The user subsequently specified 08:00–15:00 and offered an existing Intel Mac mini. See [Vercel Hobby with a seven-hour worker](scheduled-vercel.md) and [Intel Mac mini hosting feasibility](mac-mini-hosting.md): the reduced window makes Vercel's worker-memory allowance plausible, and the mini is another candidate. No host has been selected.

Checked **23 November 2026** for [Free hosting feasibility for office ordering](../issues/08-free-hosting-feasibility.md), supporting the still-open [Delivery architecture and verification approach](../issues/07-delivery-and-verification.md). Research only: no account, infrastructure, payment commitment, or architecture change was made.

## Finding

**OCI Always Free is the only evaluated free option that can preserve the agreed single Docker host. Its capacity and reclamation risks prevent treating free hosting as a dependable recovery plan.** A small paid EU VM is the simpler operational recommendation if the office accepts a modest bill. Vercel Hobby and Render Free are useful for previews, but do not satisfy this deployment as agreed. These are recommendations and engineering conclusions from the checked limits below, not provider guarantees.

The accepted target remains Caddy serving the built React SPA and proxying `/api`, modular FastAPI, a separate same-code worker, and PostgreSQL in Compose. Durable jobs must survive restarts; short runs require subminute worker polling even when no browser is open. Foreground refresh about every five seconds does not replace that worker. Daily off-host backups target at most 24 hours of data loss and manual restoration within one working day. Terraform manages infrastructure; cloud-init prepares the host and automated releases deploy the app. Encrypted, locking, versioned remote state must survive loss of that host.

| Option | Ongoing free allocation? | Fit for the agreed deployment |
| --- | --- | --- |
| Vercel Hobby | Yes, within quotas; distinct from a Pro trial | No single persistent Compose host. New free Daemons exist, but their memory quota cannot sustain even the minimum instance all month. Scheduled alternatives are too imprecise. |
| OCI Always Free VM | Yes, separate from trial credits | Technically fits. Capacity, idle reclamation, account checks and no free-tier SLA make availability/recovery conditional. |
| Render Free | Yes for selected services; free database expires | No: idle sleep, ephemeral web-service disk, expiring database and no free worker. |
| Hetzner EU VM | No | Fits the host design; provisional low-end baseline about €5.99/month before tax, domain and backup costs, subject to stock and a fresh quote. |

## Vercel Hobby: more capable than old summaries suggest, still a poor fit

**Eligibility is conditional.** The current Terms of Service (updated 19 October 2026) limit Hobby to personal **or** noncommercial use and permit changing or discontinuing the offering. An unpaid colleague project is not automatically established as commercial merely because colleagues use it at an office; company ownership, paid development or business use need clarification. Obtain Vercel's answer for the actual ownership/use if pursuing this route. Older indexed Hobby/fair-use text says personal/noncommercial more restrictively, while the live November pages differ; use the current terms rather than asserting a legal classification from the app description. [Vercel terms, Hobby section](https://vercel.com/legal/terms#hobby-plan), [current Hobby documentation](https://vercel.com/docs/plans/hobby), [Vercel help](https://vercel.com/help).

React static hosting and FastAPI are supported. A FastAPI deployment becomes one Vercel Function, rather than the agreed VM/Compose stack. The current FastAPI guide documents separate queue/workflow/scheduled integrations. Function execution has finite duration; it does not turn an ordinary HTTP application into the accepted always-running worker. [FastAPI on Vercel](https://vercel.com/docs/frameworks/backend/fastapi).

**Do not repeat the obsolete blanket claim that Vercel has no container workers.** Current Daemons documentation offers continuous Dockerfile-based workers in public beta, including Hobby, but without persistent storage. That cannot host durable PostgreSQL on the worker filesystem. [Daemons](https://vercel.com/docs/daemons).

The dedicated limits page gives Hobby **420 GB-hours/month** and **5 active CPU-hours**, with a minimum **1 GiB** instance. Memory is counted while waiting. Arithmetic: a single minimum instance exhausts 420 hours in **17.5 days**, before a complete calendar month; the default 2 GiB exhausts it in about nine days. Reaching either quota stops daemons until the next month or a paid upgrade. Generic Hobby documentation currently lists different function quotas (360 GB-hours/4 CPU-hours); do not mix those with the daemon-specific allowance. [Daemon limits and quota behavior](https://vercel.com/docs/daemons/limits), [Hobby plan](https://vercel.com/docs/plans/hobby).

Scheduling also changed: legacy Cron Jobs on Hobby run at most daily, at any point within the scheduled hour. The newer beta **Schedules** permits every 15 minutes, with a mandatory 15-minute jitter window on Hobby, including runtime-created schedules. Neither is a fit for short runs and closing reminders. Even the new Pro schedule has minute-scale jitter; exact server deadlines still need application enforcement. [Legacy cron limits](https://vercel.com/docs/schedules/cron-jobs/usage-and-pricing), [new Schedules limits](https://vercel.com/docs/schedules/limits).

A Vercel solution would therefore reopen the deployment decision: external durable PostgreSQL, an independently funded/hosted worker or a newly evaluated scheduling design, plus changed routing/operations. Hosting only the SPA on Vercel still leaves the backend host and adds another deployment surface. No such revision is approved. Five-second foreground polling also consumes function/transfer quotas; estimate it from colleagues and active hours before claiming the application fits free usage.

## OCI Always Free: feasible host, conditional operations

The live resource documentation currently allows A1 ARM compute **1,500 OCPU-hours and 9,000 GB-hours/month**, described as **2 OCPUs/12 GB** for Always Free tenancies, plus two E2 micro VMs. The older widely repeated 4 OCPU/24 GB allowance is not the current baseline. Boot/block storage has **200 GB** combined and five volume backups; Always-Free-only Object Storage has **20 GB combined and 50,000 requests/month**. Compute/volume allocations are tied to the tenancy's home region. Oracle explicitly warns that free shape capacity can be unavailable. [Current Always Free allocations](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm).

The same page permits reclaiming idle compute after a seven-day window when the documented CPU/network thresholds, and A1 memory threshold, are below 20%. A lightly used office app plausibly meets these conditions: **inference, not an observed measurement**. Artificial load is not a proposed remedy. [Idle reclamation criteria](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm#compute).

Always Free is ongoing, unlike the $300/30-day trial. Signup requires a supported credit/debit card for identity checks and may create temporary authorization holds. Oracle permits one free account per person, warns that accounts idle for 30 days can be suspended/terminated, and provides no free-tier SLA or normal Oracle Support entitlement. Upgrading to paid preserves free allowances but enables charges beyond them and cannot be reversed to a free account. Do not silently upgrade as a capacity workaround. [Oracle Free Tier FAQ](https://www.oracle.com/cloud/free/faq/).

**Fit inference:** an A1 VM can run the accepted stack and continuous worker; build ARM64-compatible images and verify all dependencies. PostgreSQL stays self-managed on a persistent mounted volume; Oracle Autonomous Database/MySQL offerings are not PostgreSQL substitutes. The low-memory E2 micro is not the recommended all-in-one target. Actual EU home-region signup, resource limits, ARM compatibility, network access and capacity remain untested. Recreating a reclaimed VM could be blocked by capacity, so the one-working-day restoration objective needs an agreed fallback or an explicit exception. Terraform reproducibility alone cannot supply unavailable hardware.

## Render Free: preview environment

Free web services sleep after 15 minutes without inbound traffic and take about a minute to wake. Their local filesystem is ephemeral and cannot use a persistent disk. The workspace shares 750 free service-hours/month. Free Postgres has 1 GB storage, expires after 30 days, then has a 14-day upgrade grace period before deletion; managed backups are unavailable. Render itself advises against production use of free instances. These conflict with durable jobs/data and unattended reminder timing. [Render Free limits](https://render.com/docs/free).

A separate continuous background worker is a supported Render service, but is outside the free service types. Cron jobs cost at least $1/month each and are not a free continuous-loop replacement. Keeping the web page open or sending synthetic wake-up requests does not create a durable database or a free worker. [Worker model](https://render.com/docs/background-workers), [cron pricing](https://render.com/docs/cronjobs#compute-plans-and-billing), [eligible free types](https://render.com/docs/free).

## Paid EU baseline: Hetzner, with a quote caveat

The official cost-optimized page lists **CX23: 2 shared vCPU, 4 GB RAM, 40 GB NVMe**, suitable as a starting sizing hypothesis; it currently renders the plan as unavailable in the retrieved page. A load/restore test must confirm sizing. [Live plan and stock caveat](https://www.hetzner.com/cloud/cost-optimized/).

The indexed official June 2026 adjustment table lists Germany/Finland CX23 at **€5.49/month excluding IPv4 and VAT**. Direct retrieval of that adjustment URL returned 404 during this research, while the live product page omitted numeric pricing. Therefore this is an **indexed official price baseline, not a verified checkout quote**. Verified general docs price a primary IPv4 at **€0.50/month excluding VAT** (IPv6 is free), producing a provisional **€5.99/month before tax** host estimate. Confirm available SKU, region and price before selecting or ordering. [Indexed official adjustment table](https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/), [IP pricing](https://docs.hetzner.com/cloud/servers/overview/#network-options).

A VM preserves the accepted deployment and ongoing worker; its storage is still not an off-host backup. Servers are billed until deletion, including while powered off. Provider disk backups have seven daily slots and exclude attached volumes, so they should not replace the required PostgreSQL-aware backup/restore procedure. [VM billing](https://docs.hetzner.com/cloud/billing/faq/), [backup scope](https://docs.hetzner.com/cloud/servers/backups-snapshots/overview/).

## Terraform, backup/state costs, and remaining work

All four providers have provider support, but support is not proof that every new beta feature has Terraform coverage:

- **OCI:** Oracle's own provider manages OCI infrastructure; verify selected VM/network/bucket/IAM resources and `user_data` against pinned versions. [Oracle provider documentation](https://docs.oracle.com/en-us/iaas/Content/dev/terraform/home.htm).
- **Hetzner:** the vendor-maintained `hcloud` provider exposes server cloud-init `user_data`, IPs, networking, firewall attachment and backup settings. Domain/DNS and any external backup/state services need their own providers. [Vendor provider](https://github.com/hetznercloud/terraform-provider-hcloud), [server schema](https://raw.githubusercontent.com/hetznercloud/terraform-provider-hcloud/main/docs/resources/server.md).
- **Vercel:** vendor-maintained Terraform provider exists. Coverage of newly documented Daemons/Schedules and external database infrastructure was **not established**; deployment configuration is not automatically Terraform resource coverage. [Provider source](https://github.com/vercel/terraform-provider-vercel).
- **Render:** official Terraform provider is available for Render resources. It does not remove free-plan limits. [Render Terraform documentation](https://render.com/docs/terraform-provider).

**A potentially zero-cost state/backup service exists:** separate OCI Object Storage buckets can hold backups and state within their combined allocation. The native Terraform `oci` backend explicitly supports conditional-object state locking and recommends bucket versioning; pin a Terraform release that supports that backend. OCI object encryption at rest is mandatory, and versioning preserves older/deleted object versions. This meets the independent-of-host state shape without another VM. Bootstrap bucket/IAM infrastructure separately, retain its state safely, and give the app backup identity no access to Terraform state. [Terraform OCI backend](https://developer.hashicorp.com/terraform/language/backend/oci), [encryption](https://docs.oracle.com/en-us/iaas/Content/Security/Reference/objectstorage_security.htm#Data_Encryption), [versioning](https://docs.oracle.com/en-us/iaas/Content/Object/Tasks/usingversioning.htm).

Object versions consume storage until removed. Budget retention across database archives, state history and lock-object versions; validate request usage and lifecycle cleanup. This can fit free allocation for a small database but **has not been sized or tested**. Same-account object storage survives host loss, not account loss. A second independently accessible copy is a useful operational improvement. [Version storage accounting](https://docs.oracle.com/en-us/iaas/Content/Object/Tasks/usingversioning.htm), [off-host regional object service](https://docs.oracle.com/en-us/iaas/Content/Object/Concepts/objectstorageoverview.htm).

Remaining possible costs: domain registration/renewal unless using an existing domain; tax; backup storage/requests beyond allocation; CI and container registry beyond their chosen plans; transfer beyond allowances; optional VM snapshots; and paid fallback capacity. No SMTP service is currently required. Web Push needs outbound HTTPS to subscription services (Apple documents `*.push.apple.com`); it does not require Apple Developer Program membership. This is protocol/platform feasibility, not a successful network test on any candidate host. [Existing push research](ios-web-push.md), [Apple sender requirements](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers).

## Recommendation and user decisions

1. **Prefer preserving the accepted architecture.** If zero compute spend is the priority, investigate OCI A1 EU capacity first without provisioning, accepting that free capacity/reclamation may defeat the recovery target. Decide whether a paid VM fallback is acceptable before treating OCI as the production plan.
2. If predictable operations matter more than zero spend, choose an available small EU VM after a fresh price/stock check. Hetzner is the baseline here; the €5.99 estimate is provisional and excludes domain/backups/tax. Do not commit to an unavailable cheap SKU or automatically select a more expensive substitute.
3. Keep Vercel Hobby/Render Free for previews if useful. A production migration to their managed model requires a new architecture/cost decision, plus Vercel eligibility clarification where relevant.
4. Before resolving Delivery architecture and verification approach, choose provider/region, ownership/billing account and spending ceiling, domain, backup destination/retention, remote-state backend/bootstrap custody, and recovery fallback. Plan implementation checks for Terraform coverage for the chosen versions, secrets injection, backup age alerting, and a timed restore drill. No provider account, live capacity, production deployment, outbound push path or restoration has been verified here.
