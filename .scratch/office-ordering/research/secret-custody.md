# Secret custody audit

2026-11-23. Planning only; recommendations below are proposals, not provisioned behavior.

**Custody.** Keep recoverable originals of PostgreSQL credentials, VAPID private key, deployment SSH private key, and backup decryption identity in the operator’s password manager. Copy deployment/runtime secrets into GitHub Actions secrets. GitHub exposes secret metadata rather than a value-retrieval API, so it is not the recovery vault. Workflow code can use—and therefore potentially disclose—secrets available to it. [GitHub secrets API](https://docs.github.com/en/rest/actions/secrets)

Use a `production` environment if supported; private repositories require Pro, Team, or Enterprise for environments/environment secrets. Required reviewers and wait timers have additional plan restrictions; do not promise approval gates. Otherwise use repository secrets and protected workflow/branch administration. [Environment availability](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments)

**Delivery/runtime proposal.** GitHub-hosted jobs receive the deployment private key temporarily; the Mini stores its matching authorized public key. Pin the Mini’s verified SSH host key. Deliver PostgreSQL/VAPID secrets over SSH to `~/Library/Application Support/coffee-app/secrets`, directory `0700`, files `0600`, owned by the deployment account. Mount only needed files into each container. The app must explicitly support reading `/run/secrets/...`; Compose does not automatically convert files into application configuration. File-backed Compose secrets use bind mounts and ignore configured `uid`, `gid`, and `mode`: validate actual Docker Desktop container readability before settling permissions. [Compose secrets](https://docs.docker.com/reference/compose-file/container-spec/#secrets)

**Registry.** Publish with job-scoped `GITHUB_TOKEN`; deployment can provisionally forward a `packages:read` job token over SSH for its authorized package, pull, then discard it. This remote-pull use needs integration verification. Tokens expire when their job finishes; manual host pulls need fresh authentication, conventionally a classic PAT with `read:packages`. Avoid a permanent PAT where practical. A temporary `DOCKER_CONFIG` alone does not guarantee avoiding Keychain: Docker defaults to detecting `osxkeychain`. Verify helper configuration and logout/cleanup on success and failure. [GHCR authentication](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry), [token lifetime](https://docs.github.com/en/actions/concepts/security/github_token), [Docker credentials](https://docs.docker.com/reference/cli/docker/login/)

**AWS/backups proposal.** Replace the earlier host schedule with a weekly Actions job: assume narrowly scoped AWS role using OIDC, SSH-trigger `pg_dump` and public-recipient encryption on the Mini, stream ciphertext to the runner, then upload to S3. The Mini needs no AWS key; decryption identity stays off-host in the vault. Gate migrations on successful pre-migration backup. Retain weekly and pre-migration objects 30 days. Encryption supports public recipients and separate private identities. GitHub schedules can delay or drop: roughly seven-day recovery-point objective assumes successful weekly runs; monitor backup age and failures. [AWS OIDC](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-aws), [age](https://github.com/FiloSottile/age), [scheduling limits](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

**Terraform/TLS.** Manage infrastructure, IAM trust and policies, not secret payloads. `sensitive` hides display but still persists values in state; protect state and bootstrap local state accordingly. Match OIDC trust to the repository’s actual subject format. Caddy’s certificate private keys belong in its persistent protected data volume, not GitHub secrets. [Terraform](https://developer.hashicorp.com/terraform/language/manage-sensitive-data), [Caddy storage](https://caddyserver.com/docs/conventions#data-directory)
